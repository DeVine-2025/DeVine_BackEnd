## 어떤 기능인가요?

관리자 신고/유저관리 기능에 남아있던 TODO 2건을 해결하고, 회원 자진 탈퇴 기능을 신규로 추가합니다.

**관리자 TODO 해결**
- 신고 처리 상태변경에서 세부 액션이 SUSPEND(정지)인 경우, 계정 정지 기능을 호출하도록 연동
- 유저 상세조회 응답에 피신고자 누적 신고/제재 이력 연동

**회원 자진 탈퇴**
- 마이페이지에서 회원이 직접 탈퇴를 신청하고 즉시 확정하는 API
- 탈퇴 확정 시 PII 즉시 익명화, 리포트 생성권/쿠폰 즉시 소멸(또는 환불 신청), 본인이 신고자인 신고이력 삭제
- 환불 신청 접수 및 관리자 조회/처리 API
- 강제탈퇴자 재가입 제한 이메일 해시 블랙리스트
- 탈퇴 유예기간 경과 후 개인정보 완전 삭제(Hard Delete) 배치

## 이 기능이 필요한 이유는 무엇인가요?

관리자 로그인 인증/인가와 관리자 유저 관리가 먼저 들어오면서, 그 이전에 만들어둔 신고 처리 기능에 "계정 정지 기능이 아직 없어서 호출 못 함" 상태로 남겨둔 TODO가 있었습니다. 이제 두 기능 다 갖춰졌으니 실제로 연동해야 합니다.

또한 회원이 마이페이지에서 직접 탈퇴할 방법이 없어 이메일 문의 등 수동 대응에 의존 중이었습니다. 개인정보보호법상 삭제 요구권 미이행 리스크가 있어 자진 탈퇴 기능을 추가합니다.

## 구현 방안 (선택)

- 회원 상태변경 이력(`MemberStatusHistory`)을 `admin.member`에서 `domain.member` 패키지로 이동합니다. domain 계층이 admin 계층을 의존하는 구조를 피하기 위함이며, 자진 탈퇴 기능에서 이 감사로그를 기록해야 하는데 그 시점에 domain 쪽 코드가 admin 쪽 클래스를 참조하게 되는 걸 막기 위해서입니다.
- 환불 신청(`CreditRefundRequest`)은 devine-core의 `domain.ticket` 패키지에 두고, 관리자 조회/처리 API는 같은 이름을 따라 `admin.ticket` 패키지로 구성합니다.
- Hard Delete 배치는 `MemberHardDeleteHandler` 전략 패턴으로 설계합니다. 회원 연관 테이블마다 정리 방식이 다르고(단순 삭제, 참조만 해제, 상태 전이 후 참조 해제 등), 이 판단을 스케줄러 한 곳에 몰아두면 새 테이블이 생길 때마다 실수가 반복되기 쉽습니다. 도메인별 핸들러로 책임을 나눠, 새 테이블이 생기면 핸들러만 추가하면 되도록 합니다.
- 환불 신청 기록(`credit_refund_request`)은 금전 청구 기록이라 하드삭제 시 무조건 삭제하지 않습니다. 미처리 상태로 유예기간이 지나면 소멸 상태로 전이해 감사 기록을 남기고, 회원 참조만 끊습니다.
